# Solar Filament Segmentation

Instance segmentation of solar filaments in GONG H-alpha full-disk images, for the
[Solar Filament Segmentation Challenge 2026](https://www.kaggle.com/competitions/filament-segmentation-2026)
(Kaggle, IEEE BigData 2026 BigDataCup). Ground truth comes from the MAGFiLO dataset
([Ahmadzadeh et al., 2024](https://doi.org/10.1038/s41597-024-03876-y)). Submissions are scored with Panoptic Quality.

See [PLAN.md](PLAN.md) for the roadmap and experiment log.

## Layout

The library (`src/filament/`) and the command-line scripts (`scripts/`) are grouped the same way, following the
pipeline: **data → model → probability maps → post-processing → submission**, with evaluation alongside.

```
src/filament/
  paths.py, tracking.py   where data/outputs live; Weights & Biases logging
  data/                   annotations (COCO → tables), images + solar disk, RLE, folds, submission CSVs
  segmentation/           per-pixel models: dataset + augmentation, U-Net family + losses, training loop, classical baseline
  detection/              instance models (Mask R-CNN), in progress
  postprocess/            probability maps on disk, connected components, component classifier, maps → submission
  evaluation/             official PQ metric, fast OOF scoring + grid search, error analysis
  analysis/               exploratory analyses behind notebooks/analysis/01_eda
scripts/
  setup/                  check_env, make_folds
  segmentation/           train, predict (OOF / test maps, TTA), run_classical
  postprocess/            tune_postprocess, fit_rescorer, ensemble_maps, make_submission
  evaluation/             evaluate (score a CSV), compare (paired ΔPQ with bootstrap CI)
  kaggle/                 build_notebooks, prepare_kaggle_dataset, summarize_kaggle_log
  figures/                figures for the notes and the report
configs/
  folds.csv               the fixed 5-fold split
  segmentation/           configs of the current models; archive/ holds screened-out experiments (see PLAN.md)
notebooks/
  analysis/               01_eda, 02_error_analysis
  kaggle/                 kaggle_train_submit (main session), kaggle_screen (parallel session); generated by
                          scripts/kaggle/build_notebooks.py
tests/                    metric equivalence, RLE/submission round-trip, folds, post-processing, training parts
notes/                    competition overview, data findings, error analysis, literature, figures/
outputs/                  checkpoints, probability maps, submissions (git-ignored)
```

Every script prints its usage with `--help`. Experiments are referred to by name (`outputs/<name>`) or by folder path.

## Setup (local, Windows/Linux)

Requires Python 3.12. PyTorch is installed separately so the CUDA build matches the GPU
(CUDA 12.8+ is required for RTX 50-series / Blackwell).

```bash
py -3.12 -m venv .venv                      # Linux: python3.12 -m venv .venv
# activate: .venv\Scripts\activate (Windows) | source .venv/bin/activate (Linux)
pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements-dev.txt         # or requirements.txt without Jupyter/pytest
pip install -e .
python scripts/setup/check_env.py
```

On Windows with Smart App Control enabled, use the official python.org build of Python, which is signed. Unsigned
builds (e.g. the Python that `uv` downloads) and some very recent package releases get their DLLs blocked. See
the comment in `requirements.txt`.

## Data

Download with the Kaggle CLI (after accepting the competition rules):

```bash
kaggle competitions download -c filament-segmentation-2026
```

Extract it into `filament-segmentation-2026/` in the repo root, or set `FILAMENT_DATA` to the
`MAGFiLO_1.0_Kaggle_2026` folder. On Kaggle the data is found automatically under `/kaggle/input`.

## Pipeline

Every model writes one probability map per image (`outputs/<exp>/oof/` for out-of-fold training images,
`outputs/<exp>/test/` for test images). Post-processing (threshold → connected components → size filter →
component classifier) is tuned separately on the out-of-fold maps against the exact competition metric.

```bash
python scripts/setup/make_folds.py              # once: configs/folds.csv (already committed)

# 1. train (writes fold checkpoints + OOF maps), then predict the test images (8-way TTA)
python scripts/segmentation/train.py --config configs/segmentation/unet_convnext_t_skel050.yaml --fold 0 1 2 3 4
python scripts/segmentation/predict.py --exp unet_convnext_t_skel050 --tta --tta-mode d8 --split oof
python scripts/segmentation/predict.py --exp unet_convnext_t_skel050 --tta --tta-mode d8

# 2. optional ensemble: average the maps of several experiments into a new experiment
python scripts/postprocess/ensemble_maps.py --exps unet_r34_skel050 unet_convnext_t_skel050 --out ens --split oof
python scripts/postprocess/ensemble_maps.py --exps unet_r34_skel050 unet_convnext_t_skel050 --out ens --split test

# 3. tune post-processing and fit the component classifier on the OOF maps (prints the honest nested estimate)
python scripts/postprocess/tune_postprocess.py --exp ens        # -> outputs/ens/postprocess.json
python scripts/postprocess/fit_rescorer.py --exp ens            # -> outputs/ens/rescorer.pkl

# 4. compare with another experiment on the same images, then write the submission
python scripts/evaluation/compare.py --a unet_convnext_t_skel050 --b ens
python scripts/postprocess/make_submission.py --exp ens         # -> outputs/ens/submission.csv
```

The classical baseline replaces step 1 with `python scripts/segmentation/run_classical.py` (experiment `classical`).

**Tracking:** training and tuning runs are logged to Weights & Biases (project `solar-filament-segmentation`, one run
per fold, grouped by experiment) when credentials are available (`wandb login`, or `WANDB_API_KEY`). Without them
nothing is logged. Force with `--set wandb=on|offline|off` (training) or `--wandb ...` (tuning).

On Kaggle, [notebooks/kaggle/kaggle_train_submit.ipynb](notebooks/kaggle/kaggle_train_submit.ipynb) runs the same
steps for a list of experiments, one training job per GPU on a T4 ×2 machine, and compares each with a baseline.
Edit the notebooks through `scripts/kaggle/build_notebooks.py`, not by hand.

Tests: `python -m pytest -W ignore::DeprecationWarning`. The metric tests compare against the organizers'
self-evaluation notebook when it is present in the repo root (it is not redistributed here).
